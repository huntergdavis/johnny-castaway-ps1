# Adding a new scene or holiday variant — memory checklist

Companion to [memory-region-allocator-plan.md](./memory-region-allocator-plan.md).
Read this before merging a PR that:

- Adds a new scene to the catalog (new ADS file or new tag in an existing
  ADS).
- Adds a new holiday variant of an existing scene.
- Changes the pack contents of any existing scene (new TTM/BMP/SCR
  references, more concurrent threads, bigger backdrops).
- Changes the pack format header structure.

If your PR doesn't touch scene data, you can skip this.

## Why this matters

After the memory-region allocator lands (v0.8.X-mem), every allocation in
jc_reborn must succeed at runtime. The allocator's regions are sized
against a static description of every scene's memory needs. If you add a
scene without updating that description, the runtime either silently
overruns (if MEM_DEV_BUILD is on — never the case in CI/release) or halts
with a fatalError at boot in the user's living room.

The static description lives in two files:

- **`docs/ps1/research/generated/scene_analysis_current.json`** — the
  scene catalog with per-scene resource peaks, thread counts, BMP/TTM/SCR
  sizes. Generated by `scripts/scene-analyzer.py` (or the renamed
  equivalent — check `scripts/`).
- **`src/generated/pack_header_metrics.h`** — the C header consumed by
  the allocator's boot-proof functions. Generated from the JSON + a
  direct read of the FG2 packs by `scripts/generate-pack-metrics.py`.

Both files are checked in. Both must be regenerated and committed in the
same PR that changes scene data.

## The checklist

1. **Author the scene.** Add/modify the ADS, TTM, BMP, SCR sources as
   normal. Build the FG2 pack.
2. **Regenerate `scene_analysis_current.json`:**
   ```sh
   python3 scripts/scene-analyzer.py --packs build/packs/ \
       --out docs/ps1/research/generated/scene_analysis_current.json
   ```
   Commit the resulting diff.
3. **Regenerate `pack_header_metrics.h`:**
   ```sh
   python3 scripts/generate-pack-metrics.py \
       --json docs/ps1/research/generated/scene_analysis_current.json \
       --packs build/packs/ \
       --out src/generated/pack_header_metrics.h
   ```
   Commit the resulting diff. The generated header includes:
   - Per-pack worst-case BOOT-buffer sizes (frame, prefetch, scratch,
     window).
   - Per-pack worst-case TRANSIENT footprint (clean-rect + setup + other).
   - Per-pack worst-case CACHE pinned working set.
   - Per-pack header CRC for runtime hash verification.

4. **Rebuild PS1.** The allocator's compile-time and boot-time checks run
   here. Expected outcomes:

   - **Clean build** ⇒ your scene fits the current budgets. Ship it.
   - **`_Static_assert` failure** for `MEM_REGION_TOTAL`, BOOT, CACHE, or
     TRANSIENT ⇒ your scene exceeds a region budget at build time. See
     "Troubleshooting" below.
   - **Runtime `fatalError` at boot** (`memVerify*` functions) ⇒ a
     specific scene exceeds budget at runtime-detected level (e.g.,
     pinned-set computation that depends on thread max). See
     "Troubleshooting".

5. **Run the 63-scene rotation** on PS1 hardware or emulator, including
   your new scene. Confirm:
   - No `fatalError` at any scene transition.
   - JCMEM telemetry (if `FG_HEAP_PROBE_LOGS` enabled) shows your scene's
     peaks within their region budgets.
   - Per-scene frame-byte diff vs. baseline either matches (if the new
     scene visually matches a reference) or is a new captured baseline
     (if this is genuinely new content).

6. **For holiday variants:** confirm `pack_header_metrics.h` enumerates
   every variant of every scene. The generator walks every reachable
   `fgLoopApplyVariant` branch automatically — if it missed yours,
   that's a generator bug, not yours. File it; in the meantime,
   manually add the variant to the metrics header.

## Troubleshooting

### `_Static_assert("MEM_REGION_TOTAL too large")` fails

Your additions pushed the BSS region buffer over 1.2 MB. Either:
- The per-scene worst-case grew (more concurrent threads, bigger BMPs)
  ⇒ Audit the scene for unnecessary resources. Can a frame be reused?
  Can a TTM share a sprite with another?
- An unrelated change to BSS pushed `_end` higher
  ⇒ Rebuild and check the linker map at `build-ps1/jcreborn.map`.
  Look for new static buffers and consider moving them through `memAlloc`.

### `fatalError("BOOT region budget exceeded")` at boot

Add up all known BOOT allocations (compile-time constants + the values
from `pack_header_metrics.h`). One of them grew. Probably the pre-sized
frame buffer because your scene is now the worst-case payload.

Options:
- **Compress the scene's payload.** Standard fare — RLE/LZ tweaks usually
  recover a few KB.
- **Raise the BOOT budget.** Edit `MEM_BOOT_BUDGET` in `mem_region.h`.
  But then a region somewhere else has to shrink — usually CACHE.
  Confirm `memVerifyAllScenesPinnedFitCache` still passes after the
  shrink.

### `fatalError("TRANSIENT region budget exceeded scene=X")` at boot

Your scene's worst-case TRANSIENT footprint (clean-rect + setup + other)
is bigger than the budget. The clean-rect estimator is the usual
suspect; check its inputs:
- Does the scene have a wider draw bounding box than its neighbors?
- Did the bounding-box estimator change recently?

Either tighten the clean-rect (smaller draw bounds → smaller snapshot),
or raise `MEM_TRANSIENT_BUDGET` and shrink CACHE.

### `fatalError("CACHE pinned working set too big scene=X")` at boot

Your scene needs more pinned resources concurrently than CACHE can hold.
Usually this means too many concurrent TTM threads.
- Can threads be serialized?
- Are there leftover dev-time test threads in the script?
- If the scene legitimately needs more, raise `MEM_CACHE_BUDGET` and
  shrink elsewhere.

## Using `MEM_DEV_BUILD` for iteration

When prototyping a scene that occasionally overruns:

```sh
cmake -DMEM_DEV_BUILD=1 ...
```

This downgrades fatalError to printf+skip during the offending scene.
**Strictly forbidden in CI and release builds.** The CI gate explicitly
fails if `MEM_DEV_BUILD=1` is detected. Use it on your local dev branch
only; flip it off before opening a PR.
