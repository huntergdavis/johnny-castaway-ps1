  RFC 9116 security.txt. Lives at the well-known location so
  responsible-disclosure tooling (and humans) can find a contact
  channel without grepping the source tree.

  Lives at /.well-known/security.txt under the project's GitHub
  Pages prefix. Jekyll-doesn't-let-you-prefix-a-permalink-with-a-dot
  caveat: the file is named `security.txt` (no leading dot) but
  `permalink: /.well-known/security.txt` ships the rendered output
  at the correct path. The relativizer leaves absolute URLs in
  `https://`-prefixed values alone, so the Contact / Canonical /
  Policy lines below survive the build's `--baseurl ""` override.

  RFC 9116 §2.5 requires the `Expires:` field to be machine-parseable
  ISO-8601 and §2.5.3 RECOMMENDS no longer than one year out. This
  file uses Liquid to render today + 1 year on each build so the
  Expires field is always fresh; same auto-extending pattern the
  industry uses to keep security.txt files from going stale.

  Coarsened to T00:00:00Z (date-only granularity) on purpose. RFC 3339
  permits any time-of-day; pinning to midnight means same-day rebuilds
  produce byte-identical output and don't churn the git diff. Same
  build-stamp-coarsening discipline that c7047365f applied to the
  generator meta + humans.txt fields.
